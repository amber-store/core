# Commit Object for jj Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the `Commit` object carry a jj commit losslessly (change id, conflicted trees with labels, empty identity names), give its key a footprint length (own bytes plus its trees), and let a directory entry point at a commit that file operations read as its tree.

**Architecture:** `commit` gains three optional fields under new CBOR keys 7–9, omitted when absent, so existing encodings do not change; `Commit.Trees()` is the single list of tree terms that the length rule, `fstree.ChildKeys` and the store's verification all use. The three directory readers in `fstree` take a commit key wherever they take a directory key and continue with its tree, so everything built on them (path resolution, tar export, `ls`, `restore`) passes through a commit without knowing. The object-graph walks need no change beyond `ChildKeys`.

**Tech Stack:** Go 1.26, `github.com/fxamacker/cbor/v2`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-23-commit-jj-design.md`

**On the form of this plan.** The executor is the author of the design and works test-first, so tasks give exact files, signatures, the tests with what each pins, and the rules; code is written during execution. Anything execution changes is recorded under "Amendments during execution".

## Global Constraints

- CBOR keys: 7 `change_id` (byte string, 1–64 bytes), 8 `conflict_terms` (array of 32-byte byte strings: an even number, 2–254, each a `DirLeaf` or `DirNode` key, repeats allowed), 9 `conflict_labels` (array of text: only with key 8, exactly `1 + len(conflict_terms)` entries, each 0–1024 bytes of valid UTF-8 without control characters, at least one non-empty). All three omitted when absent. Keys 0–6 unchanged.
- An identity's name is 0–1024 bytes (was 1–1024).
- Commit key length field = own serialized byte length + `Length()` of the tree + `Length()` of every conflict term. **Parents are not counted.** A sum that does not fit 64 bits is an error.
- `ChildKeys(commit)` = tree, conflict terms in order, parents in order.
- A commit stands for its tree (key 0), also when conflicted.
- Decoding stays strict: only the encoder's bytes are accepted.
- `commit` imports only `key`, the standard library and the CBOR library. `fstree` and `packstore` import `commit`, never the reverse.
- Verification commands preserve exit status (`set -o pipefail`) and carry a `-timeout`.
- Branch `commit-jj`, from `main`. Commit per task; do not push until the final review is done.
- Commit message style is `pkg: summary`. End every commit message with:

  ```
  Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_019kMb3Ckqnion4SKma81cfN
  ```

## Review Focus

1. **A commit that encodes the same as before must keep its bytes.** Only its key changes (the length field). Task 1, `TestEncodeMatchesHandAssembledBytes` unchanged and still passing.
2. **Length overflow**: terms whose lengths sum past 64 bits must be an error, not a wrapped value. Task 1, `TestObjectRejectsLengthOverflow`.
3. **A directory that holds a commit whose tree is missing** must fail completeness, naming the object, not pass or panic. Task 2, `TestCheckCompleteThroughACommitEntry`.
4. **Path resolution through a commit entry**, in the middle of a path and at its end, from the library and the CLI. Task 2 `TestReadersPassThroughACommit`; Task 5 `TestE2E_CommitInsideADirectory`.
5. **Commits under the old length rule** (own bytes only, as v0.0.9 wrote them) must now fail the store's verification rather than be accepted with a meaningless length. Task 3, `TestVerifyObjectChecksCommitLength`.

### Task 1: the record

**Files:** `commit/commit.go`, `commit/commit_test.go`.

**Interfaces (produces):**

```go
const (
	MaxChangeIDLen   = 64
	MaxConflictTerms = 254  // after the tree; an even number
	MaxLabelLen      = 1024
)

type Commit struct {
	Tree           key.Key
	Parents        []key.Key
	Author         Identity
	Committer      Identity
	Message        string
	Signature      []byte
	PublicKey      []byte
	ChangeID       []byte    // nil when absent
	ConflictTerms  []key.Key // the terms after Tree: remove, add, remove, add, …; nil when resolved
	ConflictLabels []string  // one per term counting Tree; nil when unlabelled
}

func (c Commit) Trees() []key.Key // Tree, then ConflictTerms
func (c Commit) Conflicted() bool
```

`Object` derives the key with length `len(bytes) + Σ Trees()[i].Length()`, checking for overflow.

**Tests:**
- Existing: `TestEncodeMatchesHandAssembledBytes` passes unchanged (Review Focus 1). `TestObjectKey` expects own bytes plus the tree's length. `TestEncodeRejectsInvalid` loses its empty-name case; `TestEncodeAcceptsBounds` gains one with both names empty.
- `TestConflictedCommitMatchesHandAssembledBytes`: map(8) with keys 0–4, 7, 8, 9 assembled by hand.
- `TestNewFieldsRoundTrip`: change id alone; terms alone; terms with labels; everything with a signature; `Decode(Encode(c))` equals `c`, `Trees()` and `Conflicted()` right.
- `TestEncodeRejectsInvalidJJFields`: one term; 256 terms; a term that is a `Blob` key, a `Commit` key; labels without terms; label count off by one; all labels empty; a label over the bound, with a control character, invalid UTF-8; a change id of 65 bytes.
- `TestDecodeRejectsNonCanonicalJJFields`: empty array under key 8; empty array under key 9; empty byte string under key 7; key 9 before key 8.
- `TestSignaturePayloadCoversNewFields`: changing the change id or a label changes the payload.
- `TestObjectLengthIsTheFootprint`: terms with lengths 300 and 70000 on top of the tree's 1. `TestObjectRejectsLengthOverflow` (Review Focus 2): a term of length `math.MaxUint64`.
- `TestGoldenVector`: the merge, re-pinned (its parents' keys changed, so its bytes did). `TestGoldenVectorConflicted`: tree the empty directory; terms `key.NewFromHash(DirLeaf, 300, 0x11…)`, `key.NewFromHash(DirNode, 70000, 0x22…)`; labels `"ours"`, `""`, `"theirs"`; change id `000102…0f`; parent the re-pinned root "a"; author Ann, committer with an **empty name**, email `bot@example.com`, Bob's time and zone; message `conflict\n`.

- [ ] Tests first, watch them fail, implement, `go test -timeout 120s ./commit`, vet, commit `commit: change id, conflicted trees with labels, empty names; the key's length is the footprint`.

### Task 2: the graph and the directory readers

**Files:** `fstree/children.go`, `fstree/dirof.go` (new), `fstree/collect.go`, `fstree/list.go`, `fstree/lookup.go`, `fstree/commit_test.go`.

**Interfaces (produces):**

```go
// DirOf returns the directory object k stands for: k itself when it is a
// DirLeaf or DirNode, the tree of the commit when it is a Commit.
func DirOf(k key.Key, get func(key.Key) ([]byte, error)) (key.Key, error)
```

`LookupEntry`, `ListEntries` and `CollectEntries` call it on the key they are given (the recursion below that never meets a commit: a `DirNode`'s children are directory objects).

**Tests:**
- `TestChildKeysCommit` gains a conflicted commit: tree, terms in order, parents in order.
- `TestReachabilityCoversEveryConflictTerm`: reachable keys include each term's objects; completeness fails when one term's blob is missing.
- `TestDirOf`: a leaf, a node, a commit, a conflicted commit (its first tree), a `Blob` key (an error), a commit whose bytes are missing (the read error).
- `TestReadersPassThroughACommit` (Review Focus 4): a tree `top/` with `vendor/` an `S_IFDIR` entry whose content key is a commit of another tree. `LookupEntry(commitKey, …)`, `ListEntries(commitKey, …)`, `CollectEntries(commitKey)`; `ResolvePath(top, "vendor/sub")` and `ResolveEntry(top, "vendor/sub/file")` through the entry; `ResolvePath(top, "vendor")` returns the commit key as stored.
- `TestDirLeafLengthCountsACommitEntry`: the leaf's length is its own bytes plus the commit key's length.
- `TestCheckCompleteThroughACommitEntry` (Review Focus 3): complete when the commit, its tree and its parents are present; fails naming the missing object when the tree, or a parent, is absent.

- [ ] Tests first, implement, `go test -timeout 120s ./fstree`, vet, commit `fstree: walks follow every conflict term; directory readers pass through a commit`.
